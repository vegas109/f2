# Firestore Data Model

Design goal: **minimize document reads** (Firestore bills per read). The core
rule is *one screen → one document read*. We denormalize aggregates onto the
user document and keep large, rarely-changing content (the curriculum) in
bundled assets, not Firestore.

> The app runs in **Local mode** by default (SharedPreferences). This schema is
> the target once `flutterfire configure` is run and `firestore` is enabled.

## Collections overview

```
users/{uid}                      ← 1 read loads the whole dashboard
  progress/{trackId}             ← per-track skill-tree progress (read on demand)
  inventory/{itemId}             ← crafted items (read only on inventory open)
  quests/{yyyymmdd}              ← today's daily quests (1 read/day)

leagues/{leagueId}               ← weekly group metadata
  members/{uid}                  ← denormalized member row (name, xp, avatar)

catalog_meta/curriculum          ← version pointer for bundled/remote content
```

## `users/{uid}` — the hot document

Loaded once at app start. Holds everything the top bar and home screen need.

```jsonc
{
  "displayName": "Ada",
  "email": "ada@example.com",
  "photoUrl": null,
  "createdAt": 1690000000000,

  // Economy (aggregates — never require reading sub-collections to display)
  "xp": 1240,
  "level": 13,
  "crystals": 85,
  "energy": 4,
  "lastEnergyRefillMs": 1690000000000,
  "streak": 6,
  "lastActiveDay": "2026-07-26",

  "selectedTrack": "python",

  // Subscription / entitlements (validated server-side on Blaze)
  "subscription": {
    "tier": "none",            // none | plus | pro | ultimate
    "expiresAt": null,
    "store": null               // play | appstore
  },

  // Small, hot progress summary so the home screen needs no extra reads.
  // Full detail lives in the progress sub-collection.
  "trackSummary": {
    "python": { "completedLessons": 42, "lastLessonId": "py_loops_3" },
    "cpp":    { "completedLessons": 8,  "lastLessonId": "cpp_hello" }
  }
}
```

## `users/{uid}/progress/{trackId}` — skill-tree progress

One document per track (`python`, `cpp`). Read only when the skill tree /
lesson list is opened, not on the dashboard.

```jsonc
{
  "trackId": "python",
  // node id -> status. Kept as a flat map for O(1) updates and 1-doc reads.
  "nodes": {
    "py_basics":      { "status": "completed", "stars": 3 },
    "py_oop":         { "status": "unlocked",  "stars": 0 },
    "py_algorithms":  { "status": "locked",    "stars": 0 }
  },
  // lesson id -> best result, for resuming and boss-fight gating.
  "lessons": {
    "py_loops_3": { "completed": true, "bestTimeMs": 41000, "mistakes": 1 }
  }
}
```

Non-linear progression (branches like "OOP" vs "Algorithms") is expressed by
each node listing its prerequisites in the **curriculum asset**, while this
document only stores *status*. Unlock logic runs on the client (and is
re-validated by a Cloud Function when rewards are granted).

## `users/{uid}/inventory/{itemId}` — crafting inventory

```jsonc
{
  "itemId": "skin_neon_owl",
  "kind": "skin",              // skin | avatar | part
  "count": 1,
  "acquiredAt": 1690000000000,
  "equipped": false
}
```

Crafting "parts" that drop from lessons are also stored here with
`kind: "part"`. Crafting consumes parts and writes a new item in one batched
write.

## `users/{uid}/quests/{yyyymmdd}` — daily quests

One document per day. A single read per day; regenerated by a Cloud Function
(or client fallback) at local midnight.

```jsonc
{
  "date": "2026-07-26",
  "quests": [
    { "id": "loops3", "title": "Write 3 loops with no mistakes", "goal": 3, "progress": 1, "rewardXp": 30, "done": false },
    { "id": "cpp2",   "title": "Finish 2 C++ lessons",           "goal": 2, "progress": 0, "rewardXp": 40, "done": false }
  ]
}
```

## `leagues/{leagueId}` and `members/{uid}`

Weekly tournaments of 30 players ranked by XP earned that week.

```jsonc
// leagues/2026-W30-bronze-0007
{ "week": "2026-W30", "tier": "bronze", "size": 30, "resetsAt": 1690500000000 }

// leagues/{leagueId}/members/{uid}  (denormalized so the board is 1 query)
{ "uid": "abc", "displayName": "Ada", "photoUrl": null, "weeklyXp": 320 }
```

The leaderboard is a single ordered query on the `members` sub-collection
(`orderBy weeklyXp desc`). Matchmaking and the weekly reset are **scheduled
Cloud Functions** — they require the Blaze plan.

## Read-cost summary

| Screen            | Reads                          |
| ----------------- | ------------------------------ |
| App start / Home  | 1 (`users/{uid}`)              |
| Skill tree        | 1 (`progress/{trackId}`)       |
| Daily quests      | 1 (`quests/{today}`)           |
| Inventory         | N items (opened rarely)        |
| League board      | 1 query (~30 docs, weekly)     |

Curriculum content is **not** in Firestore — it ships as bundled JSON assets
(`assets/curriculum/*.json`) and can later be delivered/updated via Firebase
Remote Config or a versioned Storage download keyed off `catalog_meta`.
